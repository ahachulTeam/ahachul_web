# PM 기능 명세: 홈 기반 역/호선 커뮤니티 진입 확장 (2026-02-25)

## 1. 미흡한 부분

- 현재 홈 화면에서는 커뮤니티 인기글을 `역/호선 맥락`으로 바로 확인할 수 없다.
- 커뮤니티 진입이 단일 `/community` 중심이라, 사용자가 원하는 `특정 역` 또는 `특정 호선` 맥락으로 바로 이동하기 어렵다.
- 커뮤니티 페이지 내 필터(역/호선)는 존재하지만, 홈에서 즉시 진입하는 동선이 약해 탐색 비용이 높다.

## 2. 개선 포인트

- 홈에 아래 2개 섹션을 추가한다.

1. `{선택 역} 커뮤니티 인기글`
2. `{선택 호선} 커뮤니티 인기글`

- 각 섹션에 `더보기`를 제공하고, 클릭 시 독립 페이지로 이동한다.

1. 역 커뮤니티 페이지: `/community/station/{stationId}` (one-app), `/community/station/:stationId` (vite)
2. 호선 커뮤니티 페이지: `/community/line/{subwayLineId}` (one-app), `/community/line/:subwayLineId` (vite)

- 독립 페이지 내부에서도 기존 커뮤니티와 동일하게 필터 UI를 제공한다.
- BE 신규 API는 추가하지 않는다.
  - 근거: 기존 커뮤니티 API가 `subwayLineIds`, `stationId`, `categoryType=HOT` 조합을 이미 지원한다.

## 3. 개발 진행

### 3.1 범위

- FE(one-app, vite) 구현
  - 홈 인기글 섹션 2개 추가
  - 독립 커뮤니티 페이지 2종(역/호선) 라우트 추가
  - 기존 커뮤니티 필터/목록 로직 재사용
- BE
  - 이번 범위에서는 신규 API/스키마 변경 없음
  - 기존 응답 계약 유지 여부만 확인

### 3.2 데이터/계약

- 홈 섹션 조회
  - 엔드포인트: `GET /v1/community-hot-posts`
  - 필터:
    - 역 섹션: `stationId`, `subwayLineIds`(선택 역의 대표 호선), `pageSize`(예: 3~5), `sort=createdAt,desc`
    - 호선 섹션: `subwayLineIds`, `pageSize`, `sort=createdAt,desc`
- 독립 페이지 조회
  - 기존 커뮤니티 목록/인기 목록 API 재사용
  - 초기 진입 시 URL 파라미터를 필터 초기값으로 반영

### 3.3 UX 정책

- 홈 섹션은 최대 3건 노출, 빈 데이터면 안내 문구 표시
  - 예: `해당 역 인기글이 아직 없습니다.`
- 더보기 클릭 시 해당 컨텍스트를 유지한 커뮤니티 페이지로 이동
- 기존 커뮤니티 필터 UX와 동작을 일치시켜 학습 비용을 줄인다.

## 4. 검증 결과

### 4.1 완료 조건(DoD)

- 홈에서 역/호선 인기글 섹션이 노출된다.
- 각 `더보기`가 올바른 독립 페이지로 이동한다.
- 독립 페이지에서 필터가 정상 동작한다.
- 기존 커뮤니티 목록/상세 흐름에 회귀가 없다.

### 4.2 검증 계획

- one-app
  - 홈 섹션 렌더링/링크 이동 확인
  - `/community/station/{id}`, `/community/line/{id}` 진입 및 필터 동작 확인
- vite
  - 홈 섹션 렌더링/링크 이동 확인
  - `CommunityStationPage`, `CommunityLinePage` 진입 및 필터 동작 확인
- 공통
  - FE 게이트: `type/lint/test`

### 4.3 리스크

- 특정 역/호선의 인기글이 적은 경우 빈 리스트가 잦을 수 있음
- 필터 상태 영속화(storage)와 신규 독립 페이지 상태가 충돌할 가능성
