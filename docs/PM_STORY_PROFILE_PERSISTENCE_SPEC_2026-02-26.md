# PM 스토리 기능 명세 (프로필 고정 공개형)

## 1. 배경/문제

- 기존 앱은 게시글/댓글 중심으로 기록되며, 사진 중심의 경량 공유 경험이 부족하다.
- 사용자는 인스타그램처럼 빠른 소비형 UI를 원하지만, 지하철 맥락에서는 개인 프로필에 기록으로 남는 형태도 동시에 요구된다.

## 2. 목표

- 사용자가 사진 스토리를 업로드한다.
- 업로드된 스토리는 프로필에서 지속적으로 공개된다.
- 사용자가 스토리를 삭제하면 즉시 프로필에서 사라진다.
- 썸네일 스트립/풀뷰어 중심의 인스타그램형 UX를 제공한다.

## 3. 범위

- 대상 앱: `services/ahhachul.com`(Vite), `services/one-app`(Next.js)
- 대상 화면:
  - 마이페이지(업로드)
  - 유저 프로필(공개 스토리 확인)
- 대상 서버:
  - `GET /v2/stories/me`
  - `GET /v2/members/{nickname}/stories`
  - `POST /v2/stories` (multipart: `content` + `image`)
  - `DELETE /v2/stories/{storyId}`

## 4. 정책

- 스토리는 24시간 만료가 아니라, 삭제 전까지 프로필에 유지한다.
- 삭제 권한은 작성자 본인만 가진다.
- 이미지 필수, 캡션은 선택(최대 280자).
- 공개 범위는 기존 프로필 공개 정책을 따른다(`asPublic` 기준).

## 5. UX 요구사항

- 스토리 리스트는 원형 썸네일 링(가로 스크롤)으로 표시한다.
- 썸네일 클릭 시 전체 이미지 뷰어 오버레이를 연다.
- 뷰어에서 이전/다음 이동 가능.
- 내 스토리인 경우 뷰어에서 즉시 삭제 가능.
- 업로드 영역:
  - 이미지 파일 선택
  - 캡션 입력
  - (선택) 역/호선 메타데이터 부여

## 6. 완료 조건 (DoD)

- Vite/one-app 모두 마이페이지에서 스토리 업로드 가능.
- Vite/one-app 모두 프로필에서 스토리 스트립/뷰어 확인 가능.
- 스토리 삭제 후 목록/프로필에서 즉시 제거 확인.
- FE 게이트(`type/lint/test`) 통과.
- BE Story Docs 테스트 통과.

## 7. 예외/오류 처리

- 이미지 미첨부/비정상 파일/용량 초과: 사용자 친화 메시지 노출.
- 조회 실패: 스트립 영역에 재시도 안내 메시지 노출.
- 삭제 실패: 뷰어 내 오류 메시지 노출(상태 유지).
