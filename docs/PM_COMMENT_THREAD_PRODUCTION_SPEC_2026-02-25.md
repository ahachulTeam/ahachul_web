# 댓글/답글/비밀댓글/좋아요/정렬 고도화 명세 (2026-02-25)

## 1. 미흡한 부분

- 댓글 목록이 기본 오름차순(`createdAt,asc`) 중심이라 최신 논의 파악이 느리다.
- 댓글 인기순/최신순 전환 UI가 없어 사용자가 원하는 탐색 전략을 선택할 수 없다.
- 댓글 좋아요 토글/내가 누른 상태(활성/비활성) 노출이 없어 참여 피드백이 약하다.
- 인기순 정렬 시 부모/자식 매핑이 정렬 순서에 의존하면 대댓글이 유실될 수 있다.
- one-app/Vite 간 댓글 UX가 동일하지 않아 정책 일관성이 부족하다.

## 2. 개선 포인트

- 기본 정렬을 최신순(`createdAt,desc`)으로 변경한다.
- 정렬 탭 2종 제공:
  - 최신순: `createdAt,desc`
  - 인기순: `likes,desc`
- 댓글 카드에 좋아요 액션/카운트/내 상태를 노출한다.
- 비밀댓글/답글 정책은 기존 정책을 유지하되, 정렬 변경에도 항상 동일하게 적용한다.
- BE는 댓글 조회 응답에 `likedByMe`를 포함해 FE가 안정적으로 토글 상태를 렌더링할 수 있게 한다.

## 3. UX 정책

- 댓글 섹션 헤더 우측에 `최신순 | 인기순` 세그먼트 컨트롤을 둔다.
- 기본 진입은 최신순이다.
- 정렬 변경 시 스크롤 점프를 최소화하고 목록만 재조회한다.
- 비밀댓글은 기존 정책 유지:
  - 작성자/게시글 작성자만 본문 노출
  - 그 외 사용자는 “비공개 댓글입니다.” 문구 노출
- 대댓글 정책 유지:
  - 부모 댓글에서만 “답글 달기” 노출
  - 답글은 비공개 토글 비활성(부모 정책 승계)

## 4. BE 구현 범위

- 댓글 조회 기본 정렬을 최신순으로 변경.
- 댓글 조회 결과에 `likedByMe`(boolean) 추가.
- 인기순 정렬 시에도 부모/자식 매핑이 깨지지 않도록 조립 로직 보강.
- 댓글 좋아요 API는 기존 `/v1/comments/{commentId}/likes`를 재사용.

## 5. FE 구현 범위

- one-app, Vite 모두 댓글 정렬 탭 적용.
- 댓글 카드에 좋아요 버튼/카운트/내 좋아요 상태 노출.
- 댓글 좋아요 토글 시 목록 재조회로 카운트/상태 동기화.
- 비로그인 사용자는 좋아요 클릭 시 안내 처리(기존 로그인 정책과 동일 톤).

## 6. 완료 조건 (Definition of Done)

- 최신순/인기순 전환이 one-app/Vite 모두 동작한다.
- 댓글 좋아요 토글(등록/해제)과 카운트 반영이 one-app/Vite 모두 동작한다.
- 비밀댓글/답글 정책 회귀가 없다.
- 인기순에서도 대댓글 유실/누락이 발생하지 않는다.
- FE/BE 테스트 및 린트/타입체크 게이트를 통과한다.

## 7. 예외/리스크

- 기존 데이터에 대한 `likedByMe` 계산 시 로그인 컨텍스트가 없으면 `false` 처리.
- 좋아요 중복/해제 실패는 BE 도메인 예외를 그대로 반환하고 FE는 사용자 친화 문구로 변환한다.
