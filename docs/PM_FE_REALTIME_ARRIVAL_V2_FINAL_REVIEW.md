## 1. 최종 판정
- **조건부 승인**
- 판단 근거:
  - 신뢰배지(HIGH/MEDIUM/LOW), stale fallback, 오류코드(701/704) 분기 방향은 타당함
  - 다만 FE 화면 문구와 BE 계약 필드의 예외 상황 우선순위가 일부 불명확하여 재작업 위험이 존재

## 2. Must (출시 전 필수 반영)
1. `isStale=true`일 때 고정 문구를 단일 소스로 명시하고, 리스트/상세/토스트 등 노출 위치별 동일 문구 사용을 강제할 것
2. `confidenceLevel=LOW`이면서 `etaSec=0`인 경우 표현 우선순위를 고정할 것
   - 권장 우선순위: `도착 임박` > `정보 지연` > `곧 도착`
3. 3초 자동 새로고침과 수동 새로고침 동시 발생 시 요청 중복 방지 규칙을 명시할 것
   - 동일 키 요청 진행 중에는 수동 트리거를 무시하거나 큐잉
4. `701`(데이터 없음)과 `704`(외부/스테일 모두 실패)의 UX 행동을 분리 정의할 것
   - 701: 안내 문구 + 주변역 이동 액션
   - 704: 재시도 버튼 + 마지막 성공 시각 표시

## 3. Should (품질 향상 권장)
1. HIGH/MEDIUM/LOW별 사용자 안내 문구를 QA 케이스와 1:1로 맵핑해 문서화
2. `destinationStationDirection`, `nextStationDirection` 라벨 표준을 FE 컴포넌트 규칙서에 고정
3. stale 배지와 스켈레톤 동시 노출 금지(로딩 상태 우선순위 명시)
4. 극단값(`freshnessSec>300`, `etaSec<0 보정`)에 대한 UI 표기 규칙 추가

## 4. FE/BE 협업 유의사항
1. FE: 계약 필드 누락/빈값에 대해 값 숨김 + 고정 대체문구를 사용
2. BE: `freshnessSec`, `etaSec`, `confidenceLevel`, `isStale` 계산식을 계약 테스트로 고정
3. PM: 운영 공지 문구(정보 지연/점검)의 온보딩 텍스트를 단일 문서로 관리
