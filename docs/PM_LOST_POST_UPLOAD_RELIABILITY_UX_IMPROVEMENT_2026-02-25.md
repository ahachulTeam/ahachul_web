# 유실물 작성 실패(500) 개선 PM 명세 (2026-02-25)

## 1. 미흡한 부분

- `/v1/lost-posts` 작성 시 S3 버킷 ACL 정책과 서버 업로드 옵션이 충돌하면 500이 발생한다.
- 실패 원인이 파일 업로드 정책 문제여도 사용자 화면에는 일반 실패(`INTERNAL_SERVER_ERROR`/`글 등록 실패`)로만 노출된다.
- 유실물과 동일 업로드 경로를 쓰는 커뮤니티/민원 작성도 동일 유형의 실패를 사용자 친화적으로 안내하지 못한다.

## 2. 개선 포인트

- BE는 S3 업로드에서 ACL 의존을 제거해 ACL 비활성 버킷(Bucket owner enforced)에서도 정상 업로드되도록 한다.
- BE는 파일 업로드 실패를 전용 코드(`811`)로 변환해 FE가 명확히 분기 처리할 수 있도록 한다.
- FE(one-app/Vite)는 `811` 수신 시 “이미지 업로드 실패” 문구를 인라인/토스트로 안내하고, 일반 내부오류 문구(`INTERNAL_SERVER_ERROR`)는 사용자 친화 문구로 치환한다.
- 적용 범위는 유실물 우선, 동일 업로드 경로를 타는 커뮤니티/민원 작성 UX까지 동등 기준으로 맞춘다.

## 3. 개발 진행

- BE
  - `AwsS3Client`에서 `withCannedAcl(PublicRead)` 제거
  - 업로드 실패 시 `ResponseCode.FILE_UPLOAD_FAILED(811)`로 변환
  - 임시 파일 정리(`delete`/`deleteOnExit`) 보강
  - 단위 테스트 추가:
    - ACL 없이 업로드 요청 생성 검증
    - 업로드 예외의 `811` 변환 검증
- FE(one-app)
  - 게시글 저장 에러 해석 유틸 추가
  - 유실물 에디터에서 `811` 전용 문구 노출
  - 커뮤니티/민원 에디터도 내부오류 원문 대신 사용자 친화 문구 우선 노출
  - 다국어 메시지(`ko/en/cn/th`)에 유실물 업로드 실패 문구 추가
- FE(Vite)
  - 업로드 기반 작성(유실물/커뮤니티/민원) mutation onError에서 서버 코드/메시지 파싱
  - `811`은 이미지 업로드 실패 토스트로 안내

## 4. 검증 결과

- 원인 로그: `AccessControlListNotSupported`(S3)로 500 재현 확인
- 코드 변경 후 검증 기준
  - BE 단위 테스트 통과
  - FE 게이트(type/lint/test) 통과
  - 실사용 검증 시 기대 결과:
    - ACL 충돌 500 미발생
    - 업로드 실패 시 `code=811` + 사용자 친화 문구 노출
