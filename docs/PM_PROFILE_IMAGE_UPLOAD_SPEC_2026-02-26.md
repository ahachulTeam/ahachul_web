# 프로필 이미지 선택 업로드 기능 명세 (2026-02-26)

## 1. 미흡한 부분

- 마이페이지에서 아바타 UI는 존재하지만 실제 업로드/저장 동작이 없다.
- 사용자 프로필 API(`GET /v1/members`, `PATCH /v1/members`)에 프로필 이미지 필드가 없어 FE에서 상태를 유지할 수 없다.
- one-app/vite 간 프로필 이미지 편집 기능 동등성이 맞지 않는다.

## 2. 개선 포인트

- 프로필 이미지는 **선택 사항(optional)** 으로 제공한다.
- 업로드는 기존 공통 presigned 업로드 경로를 재사용하여 비용/구현 복잡도를 낮춘다.
- 업로드 성공 시 즉시 프로필 조회 캐시를 무효화해 반영 지연을 줄인다.
- 최대 파일 용량/확장자 정책을 FE에서 1차 검증해 실패 UX를 명확히 안내한다.

## 3. 기능 범위

### 3.1 BE

- DB: `tb_member.image_url` nullable 컬럼 추가
- API
  - `GET /v1/members` 응답에 `imageUrl` 추가
  - `PATCH /v1/members` 요청/응답에 `imageUrl` 추가
- 서비스
  - `imageUrl` 입력 시 저장
  - 공백 문자열은 `null` 정규화

### 3.2 FE(vite)

- 마이 계정 페이지에서 이미지 파일 선택
- presigned 업로드 후 `PATCH /v1/members`로 `imageUrl` 저장
- 업로드 중 중복 클릭 방지, 성공/실패 토스트 제공

### 3.3 FE(one-app)

- 마이페이지 대시보드 카드에 프로필 이미지 표시
- 이미지 파일 선택 -> presigned 업로드 -> `PATCH /v1/members`
- 업로드 성공 시 프로필 쿼리 invalidate

## 4. UX 정책

- 업로드 가능 파일: `image/*`
- 용량 제한: 5MB
- 실패 메시지
  - 이미지 아님: "이미지 파일만 업로드할 수 있습니다."
  - 용량 초과: "이미지는 5MB 이하 파일만 업로드할 수 있습니다."
  - 업로드 실패: "프로필 이미지 업로드에 실패했습니다. 잠시 후 다시 시도해주세요."

## 5. 완료 조건(Definition of Done)

- 두 FE 앱에서 프로필 이미지 업로드/저장/재조회가 정상 동작한다.
- BE Docs 테스트에서 `imageUrl` 계약이 문서화되어 있다.
- 한국어 문서 제출 및 비어있지 않음 검증 통과.
