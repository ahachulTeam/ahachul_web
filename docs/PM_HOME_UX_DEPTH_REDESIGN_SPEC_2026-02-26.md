# PM 홈 UX 2~3뎁스 개편 명세 (2026-02-26)

## 1. 미흡한 부분

- 홈 화면에서 바로 투표/액션이 실행되어 정보 탐색과 실행 행위가 한 화면에 과밀하게 섞여 있었다.
- 주요 기능(투표, 커뮤니티, 유실물, 민원)의 진입점이 분산되어 있어 사용자 입장에서 “어디에서 무엇을 해야 하는지”가 명확하지 않았다.
- 투표 영역은 홈에서 즉시 선택까지 수행되어 댓글/문맥 확인 없이 반응형 클릭만 유도되는 UX였다.

## 2. 개선 포인트

- IA(정보구조)를 `요약(Home)` -> `허브(2depth)` -> `상세/작성(3depth)`로 재정렬한다.
- 홈의 역할을 “현황 요약 + 허브 진입”으로 제한하고, 실제 실행(투표/댓글/작성)은 허브/상세에서만 처리한다.
- 투표 플로우를 명확히 분리한다.
  - 1depth: 홈에서 투표 요약 확인
  - 2depth: 투표 라운지에서 실제 투표/댓글 미리보기
  - 3depth: 개별 투표 상세에서 댓글 작성/정렬/좋아요

## 3. 개발 진행

- one-app

  - 홈(`HomeViteParity`)에서 직접 투표 버튼 제거, `투표 라운지` CTA 중심으로 전환
  - 홈에 `핵심 기능 바로가기` 섹션 추가(투표/커뮤니티/유실물/민원)
  - 신규 2depth 페이지 `/daily-votes` 추가
    - 오늘의 투표 참여(좋아요/싫어요)
    - 댓글 미리보기
    - 역 투표 게시판 이동
  - 3depth 페이지의 상단 복귀 동선을 `홈`에서 `라운지` 기준으로 조정

- vite(app)
  - 신규 Activity `DailyVoteHubPage` + 경로 `/daily-votes` 추가
  - 홈 DailyVote 패널을 “요약 + 라운지 이동” 중심으로 재구성
  - 홈에 `핵심 기능 바로가기` 패널 추가(투표/커뮤니티/유실물/민원)
  - 투표 상세/역 게시판의 상단 복귀 동선을 `라운지` 기준으로 조정

## 4. 검증 결과

- FE(one-app)
  - `NX_DAEMON=false pnpm nextjs:type` 통과
  - `NX_DAEMON=false pnpm nextjs:lint` 통과
  - `NX_DAEMON=false pnpm nextjs:test` 통과
- FE(vite)
  - `NX_DAEMON=false pnpm app:type` 통과
  - `NX_DAEMON=false pnpm app:lint` 통과
  - `NX_DAEMON=false pnpm app:test` 통과

## 5. 완료 조건

- 홈에서 투표 직접 실행이 아닌 “투표 라운지 진입”이 기본 동선으로 동작한다.
- 투표 라운지(2depth)에서 실제 투표와 댓글 맥락 확인이 가능하다.
- 상세 페이지(3depth)에서 댓글 작성/정렬/좋아요가 유지된다.
- one-app/vite 양쪽에서 동일한 IA(요약 -> 허브 -> 상세) 패턴이 동작한다.
