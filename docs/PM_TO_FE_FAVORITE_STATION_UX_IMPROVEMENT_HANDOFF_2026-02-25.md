# PM -> FE 핸드오프: 즐겨찾는 역 설정 고도화 (2026-02-25)

## 1. 미흡한 부분

- Vite 저장 흐름이 비동기 완료 이전에 종료되어 실패 은닉 위험이 있음
- one-app 편집 UI가 자유 텍스트 입력 중심이라 오입력 방지가 약함
- Vite/one-app 라벨 정책이 다르고, 사용자 안내 패턴도 불일치함

## 2. 개선 포인트

- 앱 간 동등성 기준을 `stationId` 중심으로 정렬
- 저장 성공/실패 UX를 공통 패턴(로딩/토스트/이동)으로 통일
- one-app도 선택형 역 지정 UX로 개선해 오입력 가능성 차단

## 3. 개발 진행 (FE 실행 명세)

### 3.1 P0 (이번 스프린트 필수)

1. Vite 저장 로직 안정화

- 대상: `services/ahhachul.com/src/pages/my/setting.tsx`
- 요구사항:
  - `mutateAsync` 완료를 기다린 뒤 성공 시에만 `pop()`
  - 실패 시 현재 화면 유지 + 실패 메시지 노출
  - `setTimeout` 기반 강제 이동 제거

2. one-app 즐겨찾기 역 편집기 입력 방식 개선

- 대상: `services/one-app/src/app/(main-service)/me/_components/MyDashboard.tsx`
- 요구사항:
  - 자유 텍스트 역명 입력 제거
  - 역 카탈로그 기반 선택형 UI 도입(역명 + 호선 표시)
  - 중복 역 선택 사전 차단

3. 알림/확인 UI 표준화

- 대상: one-app 즐겨찾기 관련 경고/성공/실패 경로
- 요구사항:
  - `window.alert/prompt` 제거
  - 공통 토스트/모달 사용

### 3.2 P1 (연속 스프린트)

1. 라벨 정책 통일

- Vite/one-app 공통 라벨셋 또는 공통 자유입력 정책 중 하나로 확정

2. i18n 정리

- 하드코딩 문구를 메시지 리소스로 이동

3. 경로 생성 UX 미세개선

- 출발/도착 선택 기본값 충돌 방지
- 추천 경로/저장 경로 카드 정보 밀도 개선

## 4. 검증 결과 (FE 완료 시 제출 템플릿)

### 4.1 기능 검증 시나리오

1. 저장 성공: 수정 -> 저장 -> 성공 메시지 -> 화면 전환
2. 저장 실패: API 강제 실패 -> 에러 메시지 -> 현재 화면 유지
3. 중복 입력: 동일 역 2회 선택 시 저장 차단
4. 최대 개수: 4개 초과 입력 시 차단
5. 경로 생성: 출발/도착 동일 선택 시 차단, 상이 선택 시 저장 성공

### 4.2 필수 게이트

- `pnpm app:type`
- `pnpm app:lint`
- `pnpm app:test`
- `pnpm nextjs:type`
- `pnpm nextjs:lint`
- `pnpm nextjs:test`

### 4.3 완료 기준

- P0 항목 전부 반영 + 필수 게이트 통과
- Vite/one-app 동일 기준으로 저장/에러/검증 UX 동작 확인
