# PM 지하철 지연 증빙 기능 명세 (2026-02-24)

## 0. 목표
- 사용자가 "지하철 지연으로 늦는다"를 근거와 함께 빠르게 공유할 수 있게 한다.
- 단순 텍스트가 아니라 `도착예정시각 + 생성시각 + 데이터 신뢰도`가 포함된 증빙 포맷을 제공한다.
- MVP는 3탭 이내로 증빙 생성/복사/공유를 완료할 수 있어야 한다.

## 1. 핵심 사용자 시나리오
1. 출근 중 열차 지연이 발생한다.
2. 사용자는 앱에서 현재 역/노선의 도착정보를 본다.
3. `지연 증빙 만들기`를 누른다.
4. 앱이 자동으로 증빙 문구를 생성한다.
5. 사용자는 카톡/문자/이메일로 즉시 공유한다.

예시 출력 문구(사용자 커스텀 가능):
`지하철 지연으로 10:35 도착예정입니다. 생성시각 10:21, 실시간 신뢰도 MEDIUM, 최대한 빨리 가겠습니다.`

## 2. 미흡한 부분 (현재 기준)
1. 지연 증빙 전용 기능(버튼/페이지/카드)이 없다.
2. 지연 사실을 저장/재조회하는 증빙 API가 없다.
3. 공유 가능한 텍스트 템플릿/링크 토큰이 없다.
4. 위변조 방지용 서명/해시/만료정책이 없다.
5. 증빙 발급 이력 및 남용 방지(레이트리밋) 정책이 없다.

## 3. 우리가 이미 갖춘 것 (재사용 가능 자산)
1. 실시간 기반 데이터
- `GET /v2/trains/real-times`
- `generatedAt`, `isStale`, `freshnessSec`, `confidenceLevel` 필드가 이미 존재

2. 통근 맥락 데이터
- 즐겨찾는 역: `/members/bookmarks/stations`
- 역 시간 요약/막차 리스크/빠른하차/주변시설 v2 기능 일부 보유

3. 계정/권한
- 로그인/닉네임/마이페이지 플로우 보유
- 사용자별 증빙 히스토리 저장 기반으로 확장 가능

4. 프론트 기술 기반
- one-app에서 실시간 도착정보 v2를 이미 렌더링 가능
- 다국어/i18n/공통 fetchClient/모킹 인프라 보유

## 4. 개선 포인트
1. `실시간 조회`와 `증빙 발급`을 분리한다.
- 조회는 빠르게, 증빙은 서명/보관/만료를 가진 별도 리소스로 관리

2. 증빙 신뢰도 노출 규칙을 명확화한다.
- `HIGH/MEDIUM/LOW`를 문구에 직접 삽입
- stale 응답일 때 경고 문구 강제

3. 공유 UX를 단일 동작으로 단순화한다.
- 기본: 복사
- 옵션: 시스템 공유 시트(모바일), 링크 공유

4. 악용/오용 방지를 제품 요구사항에 포함한다.
- 짧은 만료시간
- 발급 횟수 제한
- 법적 효력 아님 고지

## 5. 개발 진행 명세 (MVP)
### 5.1 FE
1. 실시간 도착정보 카드/상세에 `지연 증빙 만들기` CTA 추가
2. 증빙 생성 모달/페이지
- 자동 채움: 역, 노선, 예상 도착시각, 생성시각, 신뢰도
- 사용자 입력: 수신자명(선택), 사과 문구(선택)
3. 결과 화면
- 텍스트 복사 버튼
- 공유 버튼(Web Share API 가능 시)
- 링크 복사 버튼(서버 토큰 기반)
4. 실패/오프라인 fallback
- 생성 실패 시 재시도
- stale/low confidence 배지 표시

### 5.2 BE
1. 신규 리소스: `delay proof` 발급/조회
2. 발급 시 서버가 원본 데이터 스냅샷+서명 생성
3. 만료시간/레이트리밋/중복 방지 정책 구현
4. 감사 로그(누가 언제 발급했는지) 저장

### 5.3 Infra/Security
1. 서명키 Secret Manager 관리
2. Redis 기반 rate-limit
3. 만료 배치(예: 24h)
4. 모니터링 지표
- 발급 성공률
- 발급 p95 latency
- 조회 실패율

### 5.4 QA
1. 신뢰도별 문구 검증(H/M/L)
2. stale 응답 경고 문구 검증
3. 복사/공유/링크 만료 E2E
4. 레이트리밋 초과/권한 없음/데이터 없음 케이스 검증

## 6. API 명세 (제안)
### 6.1 증빙 발급
`POST /v1/delay-proofs`

Request
```json
{
  "stationId": 201,
  "subwayLineId": 2,
  "upDownType": "UP",
  "expectedArrivalAt": "2026-02-24T10:35:00+09:00",
  "customMessage": "최대한 빨리 가겠습니다."
}
```

Response 200
```json
{
  "result": {
    "proofId": "dp_01H...",
    "issuedAt": "2026-02-24T10:21:12+09:00",
    "expiresAt": "2026-02-25T10:21:12+09:00",
    "confidenceLevel": "MEDIUM",
    "isStale": false,
    "text": "지하철 지연으로 10:35 도착예정입니다. 생성시각 10:21, 신뢰도 MEDIUM.",
    "shareUrl": "https://ahhachul.com/proofs/dp_01H..."
  }
}
```

### 6.2 증빙 조회(공유 링크)
`GET /v1/delay-proofs/{proofId}`

- 만료 시 `410 GONE`
- 위변조/미존재 시 `404 NOT_FOUND`

## 7. 데이터 모델 (제안)
### 7.1 delay_proof
- `id` (PK)
- `member_id`
- `station_id`
- `subway_line_id`
- `up_down_type`
- `expected_arrival_at`
- `confidence_level`
- `is_stale`
- `snapshot_payload_json`
- `signature`
- `issued_at`
- `expires_at`
- `created_at`

### 7.2 delay_proof_audit
- `id`
- `proof_id`
- `event_type` (`ISSUED`, `VIEWED`, `EXPIRED`)
- `actor`
- `created_at`

## 8. 정책
1. 법적 효력 아님 문구를 모든 증빙 화면에 고정 노출
2. 증빙 만료 기본 24시간
3. 사용자별 발급 제한(예: 분당 3회, 일 50회)
4. LOW/STALE일 때 문구에 `정확도 낮음` 자동 포함

## 9. 단계별 로드맵
### Phase 1 (MVP, 1 sprint)
- FE 증빙 생성/복사 UI
- BE 발급/조회 API
- 기본 rate-limit 및 만료

### Phase 2
- 링크 페이지 고도화(지도/노선 시각화)
- 알림/메시지함 연동
- 다국어 증빙 텍스트 강화

## 10. 완료 조건 (Definition of Done)
1. PM 승인된 문구/정책 반영
2. FE: 단위 테스트 + 공유 시나리오 통과
3. BE: 컨트롤러/서비스 테스트 + 만료/레이트리밋 테스트 통과
4. QA: 주요 시나리오 Pass 리포트 작성
5. 운영: 대시보드/알람 설정 완료
